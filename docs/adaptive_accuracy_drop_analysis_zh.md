# MMStar 自适应引导准确率下降分析

> 本报告分析的是 `039d3877e61d0bc1` 的历史运行；该运行使用未归一化的
> `weighted_sum`。后续代码已将非零选择权重归一化，新实验应使用新的 `run_id`
> 重新生成结果，不能把本报告的 57.00% 当作归一化方案的效果。

## 分析对象与结论

本报告分析 `run_id=039d3877e61d0bc1` 的 [300 条选择记录](../outputs/adaptive_selections/039d3877e61d0bc1.jsonl)和 [300 条配对生成记录](../outputs/adaptive_generations/039d3877e61d0bc1.jsonl)，并用 [指标文件](../outputs/adaptive_metrics/039d3877e61d0bc1.json)、[运行清单](../outputs/manifests/07_run_adaptive_steering.json)、MMStar 题目元数据及同一批向量的固定方向扫描作交叉检查。两份 JSONL 均有 300 个唯一 `item_identity`，逐题完全匹配，且所有记录状态均为 `ok`；选择器没有报错。

**主要结论：降点的最大可观察来源是干预后生成陷入长篇重复，未输出可评分的最终选项。** 300 题中，基线答对 197 题（65.67%），自适应干预答对 171 题（57.00%），净少 26 题，即 **−8.67 个百分点**。40 道“对变错”中，22 道干预回答超过 2 万字符、反复重复内容且没有 `Final Answer`；另 1 道给出正确答案，但加粗格式未被解析；其余 17 道确实选择了错误选项。14 道“错变对”抵消了一部分损失。

这说明当前结果同时包含**生成稳定性问题、一道评分格式问题和真实选项退化**。`weighted_sum` 合成后向量过强、并在每一步解码持续注入，是最值得优先验证的机制；现有记录能证明两者与失败相关，尚不能单凭观察数据证明因果。

## 实验设置与原始对照

运行清单记录：本地 Qwen3-VL-8B-Instruct，MMStar 前 300 题，每种能力使用 128 对对照样本，目标解码层 23，`mean_norm` 向量；后端为 `vllm_hook_v0_2`，`phase=both`、`positions=last_token`，第二轮 `max_new_tokens=8192`。第一轮以温度 0.6 为六种能力选取 `[0,1]` 权重，第二轮将六个向量按 `weighted_sum` 相加，`global_scale=1.0`，基线和干预均以温度 0 生成。相关行为见 [向量合成](../src/mllm_self_steering/adaptive.py)、[两轮生成](../src/mllm_self_steering/adaptive.py)及 [vLLM 请求构造](../src/mllm_self_steering/models/vllm_hook.py)。

| 配对结果 | 题数 | 对准确率差的贡献 |
| --- | ---: | ---: |
| 基线对、干预对 | 157 | 0 |
| 基线对、干预错 | 40 | −13.33 个百分点 |
| 基线错、干预对 | 14 | +4.67 个百分点 |
| 基线错、干预错 | 89 | 0 |
| **合计** | **300** | **−8.67 个百分点** |

按这 300 道题作配对检验，40 对 14 的不对称性对应双侧精确 McNemar 检验 `p≈0.00054`；按题目配对重采样 20,000 次、随机种子 42 得到准确率差的 95% 百分位区间约为 **[−13.33, −4.00] 个百分点**。这些值刻画本次样本的不确定性，不能代替跨种子、跨题集的复现。

## 原因一：大量干预输出进入重复循环

| 输出状态 | 基线 | 自适应干预 |
| --- | ---: | ---: |
| 超过 20,000 字符 | 3/300 | 41/300 |
| 无法解析出选项 | 3/300 | 43/300 |
| 其中：基线原本答对而干预后超过 20,000 字符 | — | 22/300 |

这里的“超过 20,000 字符”是对异常长输出的**分析阈值**，不是代码内设置的终止条件。41 条长干预输出都没有被解析出选项。将输出转为小写单词后，按连续 8 个词组成 n-gram，计算 `1−不同 n-gram 数/全部 n-gram 数`：长输出的重复比例中位数为 **98.7%**（最低 89.7%），其他 259 条的中位数为 **0%**。人工查看其首尾，也能看到句子、描述或候选项持续重复，结尾常截在句中。例如：

| 题目 | 基线 → 干预 | 可观察现象 |
| --- | --- | --- |
| `mmstar_20` | 正确 B → 无答案 | 36,889 字符；反复写“person is riding the horse”，结尾停在半句。 |
| `mmstar_71` | 正确 C → 无答案 | 43,880 字符；反复描述圣诞树与建筑，没有最终选项。 |
| `mmstar_89` | 正确 A → 无答案 | 28,735 字符；不断重复“A/B/D is correct”，无法收敛。 |
| `mmstar_194` | 正确 D → 无答案 | 38,409 字符；已多次说 D 是正确 caption，但仍持续重复，最后没有符合评分格式的答案。 |

这 22 条长输出占总净降点的 **7.33 个百分点（22/300）**：它们本来正确，干预后都记错。更准确的说法是“22 个净损失题目落在这种失败模式中”，并不表示只要缩短输出就一定能恢复这 22 题。JSONL 没有保存 vLLM 的 `finish_reason`，因此只能根据长度、重复和半句结尾判断它们**很可能**耗尽 8192 token 配额，不能直接证实每条请求的终止原因。

## 原因二：合成向量强度与长输出强相关

Stage 03 的六个 `steering` 向量范数都约为 **61.64**，见 [向量元数据](../outputs/vectors/d2cccf44d1592927/capability_vectors.json)。Stage 07 当前使用 `weighted_sum`：`v = Σ w_i v_i`，不会按权重之和重新归一化。选择器经常同时给多个视觉能力高权重：`vision_detail` 非零 258/300，`vision_grounding` 非零 271/300，`vision_spatial` 非零 165/300；其中 `vision_detail` 的权重有 202 题为 0.75，`vision_grounding` 有 271 题为 0.75 或 1.0。合成向量与单个向量最大范数之比平均为 **1.488**，有 25 题超过代码的 2.0 警戒值，最高 **2.360**。

| 权重／范数分组 | 题数 | 长输出（>20,000 字符） | 对变错 | 错变对 | 净变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 全部权重为 0 | 25 | 1 | 0 | 0 | 0 |
| `0 < Σ权重 < 2` | 34 | 0 | 5 | 4 | −1 |
| `2 ≤ Σ权重 < 3` | 139 | 8 | 13 | 7 | −6 |
| `Σ权重 ≥ 3` | 102 | 32 | 22 | 3 | **−19** |
| 合成范数比 `> 2` | 25 | 15 | 6 | 2 | −4 |

高权重组的长输出比例为 **32/102=31.4%**；较低且非零的权重组为 **8/173=4.6%**。范数比超过 2 的组为 **15/25=60%**；其余非零干预组为 **25/250=10%**。这些是明显的剂量关联，支持“合成强度过大导致解码不稳定”的假设。但选择器是按题目选权，题目难度和题型会混杂这个关系；需要保持题目与权重不变、只改变全局尺度来做因果检验。

有一种高频模板尤其值得检查：`(text_logic,text_quantitative,text_relevance,vision_detail,vision_grounding,vision_spatial)=(0,0,0.75,0.75,0.75,0.75)` 出现 **35 次**，其中 **11 次长输出、11 次对变错、0 次错变对**。这些题目中的 26 道属于 `image scene and topic`，故模板表现也受题型影响。单看 `vision_spatial>0.5` 的 92 道题，出现 26 次长输出、22 次对变错、3 次错变对；这提示其参与的大权重组合值得消融，不能据此断言空间向量单独有害。

向量之间还存在同向叠加：`vision_detail` 与 `vision_grounding` 的余弦相似度约 **0.336**，`text_relevance` 与 `vision_grounding` 约 **0.143**，见 [相似度矩阵](../outputs/metrics/d2cccf44d1592927_vector_similarity.json)。因此“每个权重都不超过 1”不能保证合成干预强度不超过单向量。

## 原因三：其余真实错选与一道解析失误

剔除上述 22 道长输出后，剩余对变错为 18 道：**17 道输出了错误选项，1 道是格式解析失误**。错选不是纯粹的评分器问题，原始文本显示模型确实改变了视觉证据或选项取舍：

| 题目 | 正确项／基线 → 干预 | 回答变化 |
| --- | --- | --- |
| `mmstar_11` | D → C | “主要特征”由具体的 buildings 改判为更概括的 city skyline。 |
| `mmstar_25` | B → D | 将朦胧／阴天的图像改判为晴天。 |
| `mmstar_34` | D → B | 将舞台主色从黑色改判为蓝色灯光。 |
| `mmstar_48` | B → C | 将主要焦点从舞鞋改判为芭蕾舞者。 |

`mmstar_152` 的干预输出末尾是 `**Final Answer: C**`，金标和基线都是 C；[现有解析器](../src/mllm_self_steering/evaluation/answers.py)只接受未加粗的行末 `Final Answer: C`，因此返回 `None`。单独修复此格式最多使本报告的干预准确率增加 **1/300=0.33 个百分点**，不足以解释主要降点。

把净变化按可观察模式拆开：**22 个长输出损失 + 1 个格式损失 + 17 个真实错选 − 14 个真实获益 = 净损失 26 题**。若只修正 `mmstar_152` 的解析，57.00% 会变成 **57.33%**。对于 22 个长输出，不能直接把它们假定为“本应正确”；仅作为乐观上界，若它们全部恢复且其他答案不变，准确率才会到 **64.33%**；再修复加粗解析，上界为 **64.67%**。

## 题型差异与固定方向扫描

| MMStar 类别 | 题数 | 基线准确率 | 干预准确率 | 对变错 / 错变对 |
| --- | ---: | ---: | ---: | ---: |
| coarse perception | 250 | 73.2% | 62.4% | 34 / 7 |
| fine-grained perception | 50 | 28.0% | 30.0% | 6 / 7 |
| 其中：image scene and topic | 141 | — | — | 27 / 4 |

净降点主要集中于前 300 题中占多数的粗粒度视觉题，尤其 `image scene and topic`。这可能与选择器在此类题上同时打开多个视觉方向有关，也可能与题目顺序／难度有关，不能推断完整 MMStar 的分布。

[Stage 05 固定方向扫描](../outputs/metrics/5d5ad3cb7e7f068e_steering_metrics.json)使用同一模型、128 对向量及 300 道 MMStar 题：例如单独 `vision_grounding` 在 `α=-0.5` 时为 70.67%，`α=+1` 时为 63.33%；`vision_spatial` 在 `α=+0.5` 时为 67.67%。它说明方向的符号与强度并非“越大越好”，可为下一轮尺度实验提供候选值。**但 Stage 05 的 `max_new_tokens=2048`，Stage 07 是 8192，且请求并发设置不同；两次运行的基线分别为 65.33% 与 65.67%，不能把两张表当作严格同条件的因果比较。**

## 优先验证的实验

1. **先记录终止原因。** 在生成 JSONL 中保存 `finish_reason`、实际生成 token 数和是否含可解析最终答案；对相同 300 题复跑，确认长输出是否真由长度上限截断。可同时统计重复 n-gram，但不要仅靠字符数判定循环。
2. **固定第一轮权重，只扫描第二轮强度。** 对同一 300 题复用已保存的选择结果，比较 `global_scale=0.25/0.5/1.0`、`weighted_sum` 与 `weighted_mean`，以及合成向量范数上限。共同报告准确率、对变错、错变对、长输出率，并保持生成 token 上限与服务端设置一致。这是检验“向量过强”的首要实验。
3. **比较 `phase=prefill` 与 `phase=both`。** 当前 v0.2 后端在 `both` 下对最后一个提示 token 和每一步解码都加向量；若只在 prefill 注入显著降低重复长输出，可定位持续解码干预的作用。
4. **做能力组合消融。** 在同一批题和同一尺度下，依次关闭 `vision_spatial`、只保留一个视觉方向、以及关闭 `text_relevance`；观察长输出率和真实错选数是否同步变化。特别检查上述 35 道高频权重模板题。
5. **单独修正评分解析并重算。** 接受行末的 Markdown 加粗 `**Final Answer: C**`，同时保留原始输出和解析版本；该修正只能解释 1 题，不能替代生成稳定性实验。

## 解释边界

这是一组单模型、单种子、MMStar 前 300 题的观察结果。记录没有 `finish_reason`，也没有对同一道题逐一测试“相同向量但不同尺度／注入阶段”的反事实，因此不能确定具体是某个能力、某一层还是 vLLM-Hook 实现导致循环。当前的 steering probe 只检查首 token 概率是否变化，能确认干预被服务端接受并产生影响，**不能保证回答质量或解码稳定性**。上述建议按能否直接区分这些机制排序。
